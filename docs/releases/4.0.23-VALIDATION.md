# Release 4.0.23 verification

Verified on October 18, 2026, using Java 21.0.10 and Minecraft 1.21.1.

| Check | Result | Evidence |
| --- | --- | --- |
| NeoForge and Fabric production builds | Both succeeded | Local `build/release-4.0.23-build.log` |
| Metadata, unique ZIP entries and JSON validity | Both main archives passed; 3,962 JSON entries per archive | Local `build/release-4.0.23-audit.json` |
| Comparison with the manually tested local fix | All ordinary classes and resources are identical; only loader version metadata and the version-derived Architectury helper package name differ. The normalized helper disassembly is identical. | Local `build/release-4.0.23-audit.py` |
| Development-source/resource isolation | All six main, source and dev-shadow archives passed; no compost probe is bundled | `tests/starfield/verify_release.py` and archive audit |
| Final NeoForge production JAR | 98/98 dedicated-server checks passed | `tests/compost/SeedCompostProbe.java` |
| Manual client check of the local fix before the version bump | Maintainer confirmed it works | Separate test client; confirmation on October 18, 2026 |

The regression probe ran against the final production NeoForge JAR on three separate ordinary dedicated servers using NeoForge 21.1.226 and Resourceful Config 3.0.11. Each server loaded its configured chance from disk and repeated its checks after a real resource reload:

| `core.seed_compost_value` | Checks | Expected behavior |
| --- | ---: | --- |
| `0.3` | 32 | Seeds are consumed; an empty composter gains its first layer; the data map reports exactly 0.3 |
| `0` | 32 | Right-clicks and top-face hopper insertion reject seeds without consuming them |
| `1` | 34 | Accepted seeds always raise the compost level while it can accept input |

Player interactions use a survival fake player through `ServerPlayerGameMode.useItemOn`, exercising normal NeoForge interaction events. Seeds with and without genome components are checked separately. Top-face item-handler insertion and simulation verify the composter's hopper interface; simulation must not fill the composter. Partially filled and processing composters are checked, and the vanilla wheat-seed chance must remain 0.3. The standalone probe stops each server and writes its results. It is outside the production source sets.

The original 4.0.21 bug was reproduced separately: the obsolete vanilla map contains 0.3 while NeoForge's actual composter lookup returns -1 and refuses the seeds. The fix updates NeoForge's compostable data map after each server-side data-map load. Client synchronization does not replace the server's chance with the client's local configuration.

Fabric passed build and archive validation. No Fabric gameplay session or unrelated integration suite was run for this patch.
