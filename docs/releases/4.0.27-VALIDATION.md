# Release 4.0.27 verification

Verified on November 11, 2026, using Java 21.0.10, Minecraft 1.21.1, NeoForge 21.1.226 and Fabric API 0.116.11+1.21.1.

| Check | Result | Evidence |
| --- | --- | --- |
| NeoForge and Fabric production builds | Both succeeded after cleaning the `common`, `neoforge` and `fabric` projects | `./gradlew :common:clean :neoforge:clean :fabric:clean :neoforge:build :fabric:build` |
| Development content isolation | All six main, source and dev-shadow archives passed | `tests/starfield/verify_release.py` |
| Release contents and metadata | Loader metadata reports `4.0.27`; `RegistryDataLoaderMixin` is listed in `agricraft-common.mixins.json` and present in both main archives; the new config translation is present in both | Archive listing |
| NeoForge, option `false` | Plants: only `minecraft:wheat` from the test datapack. Mutations: none. Soils: all 10 | Dev server, see below |
| Fabric, option `false` | Plants: only `minecraft:wheat` from the test datapack. Mutations: none. Soils: all 10 | Dev server, see below |
| NeoForge, option `true` | 173 plants and 46 mutations, the same as without the option | Dev server, see below |

## Server run

Each loader's development server was started on a new world. The world held a datapack with a copy of the built-in `minecraft:wheat` plant definition and a `load` function that ran `/agricraft_dump plants`, `/agricraft_dump mutations` and `/agricraft_dump soils`. The registry lists were read from the server log. The mixin applied on both loaders without errors. This confirms that the AgriCraft jar's pack id, `mod/agricraft` on NeoForge and `agricraft` on Fabric, is detected, and that a datapack override of a built-in id survives.

## Limits

Only dedicated development servers were run. Production clients, the singleplayer config screen and existing worlds were not tested. Mutations from compatibility packs that point at disabled plants were not tested in game. They are filtered out by the existing check that a mutation's plants are present.
