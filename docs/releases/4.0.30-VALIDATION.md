## Fluid client run

`compat-review/fluidlogging-2026-11-18/run_probe.py` builds the separate test mod `tests/fluidlogging/FluidloggingProbe.java`, which registers its own fluid `fluidprobe:quicksilver` and a datapack plant that needs it, and starts the client three times: with the fluid listed in `core.fluidloggable_fluids`, again after a restart, and with the list emptied. The main stage covers the block state property and count, buckets (pouring, a second fluid, picking up), placing sticks inside the fluid, draining with a Create open-ended pipe (once, not endlessly, also for lava and water), growth conditions (a plant that needs the fluid, a poppy, and lava burning both the fluid plant and kelp), removing the plant or its soil, and the client/server list comparison including the disconnect message.

## JEI client run

`compat-review/jei-seed-transfer-2026-11-24/run_probe.py` builds the separate test mod `tests/jei/JeiTransferProbe.java` and starts a client with JEI. Through JEI's runtime API it asks the player inventory's transfer handler to fill AgriCraft's Journal recipe (writable book + `#agricraft:seeds`), first without seeds, then with AgriCraft seeds only, then performs the transfer and reads the crafting grid.

## Limits

The Fabric build uses the same common code and was not run in game; Fabric has no JEI in the development setup. Only the player inventory's 2x2 grid was tested for the transfer; the crafting table uses the same JEI matching code. The extra fluid was a test mod's fluid, not a fluid from a published mod.
